## Integration decisions

- No Golem adapter is presented as working because this environment is Windows and lacks Yagna/provider services. A future adapter must verify the supported Linux runtime, payment account, VM image packaging, GPU capabilities, and independently check offer prices before quote creation.
- libp2p is integrated as a standalone peer-transport package. Its public GossipSub topic and direct private RPC are not yet connected to the customer/miner workflow or settlement path. mDNS is local-network discovery; remote networks need configured bootstrap addresses or another discovery adapter. GossipSub is best effort, and direct event anti-entropy on connection is eventual synchronization, not a global consensus log.
- Helia storage is implemented behind an explicit adapter. Public writes require caller authorization; private writes store ciphertext and return out-of-band grants. This does not make a CID private, guarantee global pinning/deletion, or establish recipient identity. The adapter remains disconnected from the customer/miner workflow. OrbitDB is still not integrated and must keep private task state outside public databases.
- The EVM contract accepts an existing ERC-20. It has no token issuance, but its verifier assignment evidence hash is not a drand verifier. The Python demo continues to use the local idempotent ledger.
- The optional MCP server routes declared skill execution through a killable worker and exposes no filesystem or shell tools to the model. Process `cwd`/environment controls are not a hardened OS sandbox; the worker still runs as the miner's OS user, Ollama is outside worker resource accounting, and production filesystem/network isolation remains required.
