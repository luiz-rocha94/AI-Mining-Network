# Integration and compatibility matrix

The development environment is Windows. A local Ollama service is available and the UI has discovered its installed models; a live document task was run with `qwen3:4b-instruct`. No Yagna service, IPFS peer, persistent EVM RPC, or EAS deployment is attached. Integrations below are marked according to code and test evidence, not intended architecture.

| Project | Current use | Compatibility / constraints verified | Status |
|---|---|---|---|
| Agent Skills | `skills/invoice-extractor/SKILL.md` and JSON manifest; local parser and package hash | Skill folder requires `SKILL.md` with YAML frontmatter (`name`, `description`). Local parser intentionally supports simple frontmatter fields used by this sample. [Specification](https://openagentskills.dev/docs/specification) | Implemented local format, not a remote registry |
| Ollama | Direct HTTP `/api/tags`, `/api/chat`, JSON-schema format, temperature 0; model digest in benchmark and receipt | Structured outputs accept a JSON Schema in the `format` request field. [Official guide](https://docs.ollama.com/capabilities/structured-outputs) | Real local adapter; live invoice task exercised with `qwen3:4b-instruct`; model replay remains a consistency check, not proof of factual correctness |

## Integration decisions

- No Golem adapter is presented as working because this environment is Windows and lacks Yagna/provider services. A future adapter must verify the supported Linux runtime, payment account, VM image packaging, GPU capabilities, and independently check offer prices before quote creation.
- Helia/OrbitDB are not added as dependencies just to claim a connection. When implemented, storage must be split into public metadata/public skills and encrypted, access-controlled private task artifacts. OrbitDB replication should be tested through two independent peers and partition/rejoin conditions.
- The EVM contract accepts an existing ERC-20. It has no token issuance, but its verifier assignment evidence hash is not a drand verifier. The Python demo continues to use the local idempotent ledger.
- The optional MCP server calls the same local Ollama extractor. It does not grant filesystem access or arbitrary tools to the model.
